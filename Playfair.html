Step by step

How it works
  1. Remove the J: it is replaced by I. Keep letters only.
  2. Cut the text into pairs. If a pair has two equal letters, insert the padding letter (X by default) between them. If the length is odd, add the padding letter at the end.
  3. Same row: take the letter to the right (encrypt) or to the left (decrypt).
  4. Same column: take the letter below (encrypt) or above (decrypt).
  5. Rectangle: swap each letter with the one in the same row, in the other corner.
Security flaws
  • Digraph frequency analysis: there are only 600 possible pairs, so common pairs (like TH or HE) still show up in the ciphertext.
  • Small key space: the table has 25 letters, and a short or common key can be guessed by brute force or dictionary attack.
  • Known plaintext: if an attacker knows some plain and cipher pairs, the table can be rebuilt.
  • Reversed pairs: if AB becomes XY, then BA becomes YX. This pattern leaks information.
  • Letters only: spaces, numbers and the J/I difference are lost, so the decrypted text may need manual fixing.
  • Padding letter: the extra letters are easy to spot.

Fix ideas: use a long random key, avoid reusing the same key, and use modern encryption (like AES) for real data.
