Hill Cipher

Encrypt pairs of letters using a matrix.

Principle

Each letter is converted into a number (A = 0 ... Z = 25). The message's letters are encrypted two at a time (x, y) using a 2×2 key matrix modulo 26:

First letter = (a·x + b·y) mod 26
Second letter = (c·x + d·y) mod 26

Decryption uses the inverse matrix. This inverse exists only if the determinant (a·d − b·c) is coprime to 26.

The input accepts uppercase and lowercase letters. The wrapper preserves original case, spaces, punctuation, digits, and Unicode characters. Compact encrypted metadata restores them after decryption without storing a verbose JSON object for every character.

Padding: if the number of letters is odd, an X is added before encryption. The implementation records the original letter count in protected metadata, so it removes only the added padding and does not accidentally remove an original final X.

Hill Cipher Weaknesses

  • Linearity: encryption uses matrix multiplication modulo 26. Suitable known plaintext/ciphertext pairs can reveal the key through algebraic calculations.
  • Known-plaintext attack: for a 2×2 matrix, two plaintext blocks and their ciphertext blocks may recover the key if the plaintext-block matrix is invertible modulo 26. Otherwise, additional blocks may be needed.
  • Chosen-plaintext attack: an attacker who can request encryption of selected blocks may recover the columns of the key matrix.
  • Small key space: there are 157,248 invertible 2×2 matrices modulo 26, so exhaustive search is practical.
  • Additive homomorphism: the classical Hill transform preserves addition modulo 26, which enables algebraic manipulation.
  • Limited diffusion: each block is transformed independently; a change in one plaintext block does not propagate to other blocks in the classical algorithm.
  • Zero block: AA represents (0, 0), and K × (0, 0) = (0, 0), so AA encrypts to AA under the classical Hill transformation.

Key Matrix Validity

For the matrix K = [[a, b], [c, d]], the determinant is:

det(K) = a × d − b × c

The determinant can be negative; it does not have to be positive. The exact condition for the key matrix to be invertible modulo 26 is:

gcd(det(K), 26) = 1

Since 26 = 2 × 13, the determinant must be odd and must not be divisible by 13.

  • det = −1: valid, because −1 ≡ 25 (mod 26) and gcd(25, 26) = 1.
  • det = 9: valid, because gcd(9, 26) = 1.
  • det = 0: invalid.
  • det = 13: invalid.
  • det = 4: invalid.

The program validates this condition before encryption and decryption. A valid determinant makes decryption possible, but does not remove Hill's cryptographic weaknesses.

The wrapper below compactly encodes, encrypts and authenticates formatting metadata so spaces and case are not plainly visible in the package. The underlying Hill ciphertext remains vulnerable to classical attacks; see “What We Improved — and What Remains.” This is an educational demonstration, not a modern secure cipher.

What We Improved — and What Remains

Important: the Hill matrix transformation itself has not been changed. The items below describe improvements around the classical algorithm; they do not remove Hill's mathematical weaknesses.

  • Original spaces, punctuation, digits, Unicode and letter case — improved: formatting is stored as compact binary metadata, encrypted with AES-GCM, and restored after decryption. The transmitted package has no literal spaces. However, the package length and the separate Hill-ciphertext field still reveal some information about the message length and number of letters.
  • Ambiguous final X padding — fixed at the wrapper level: the authenticated formatting metadata records how many original letters were present. After Hill decryption, the program restores only that number of letters instead of guessing whether a final X was padding. A padding X may still be added internally when the number of letters is odd.
  • Package modification — partially addressed: HMAC-SHA-256 authenticates the package fields, and AES-GCM authenticates the encrypted formatting metadata. A modified package should be rejected. However, the wrapper keys are derived from the Hill matrix, whose key space is small, so this does not provide strong security against an attacker who recovers or brute-forces the Hill key.
  • Invalid key matrices — handled by validation: the program checks gcd(det(K), 26) = 1. A negative determinant is allowed when it is invertible modulo 26; the determinant is normalized before the check. This prevents invalid-key errors but does not make a valid Hill key more resistant to attack.
  • Linearity, known-plaintext attacks and chosen-plaintext attacks — not fixed: the original Hill transformation remains linear. The attack panel demonstrates how suitable plaintext/ciphertext blocks can reveal the key matrix.
  • Small key space, additive homomorphism, zero-block property and limited diffusion — not fixed: these properties follow from the classical Hill transformation. Formatting protection and an integrity tag do not remove them.
  • Repeated-block patterns — not fixed in the Hill ciphertext: identical plaintext blocks still produce identical ciphertext blocks under the same matrix. The random salt changes the protected metadata but does not randomize the classical Hill ciphertext itself.

Conclusion: this implementation improves formatting restoration, padding handling, key validation, and detection of package changes. It does not make the classical Hill cipher secure against cryptanalysis. The wrapper is for coursework and demonstration, not for protecting real confidential data.

Try It

Attacker: Known-Plaintext Attack

The attacker knows a plaintext and the corresponding Hill ciphertext. Since Hill is linear, the attacker can solve K · P = C and recover the key when the selected plaintext blocks form an invertible matrix modulo 26.
