How it works
  1. Letters A-Z are prepared for Playfair. J is represented by I inside the 5x5 grid. Original letter case, J/I choices, spaces, punctuation, digits, and other characters are saved in encrypted metadata so they can be restored after decryption.
  2. The text is divided into pairs. If a pair contains two identical letters, a filler is inserted between them. If the final letter has no partner, a filler is added. The exact filler positions are recorded in encrypted metadata.
  3. Same row: move right to encrypt or left to decrypt.
  4. Same column: move down to encrypt or up to decrypt.
  5. Rectangle: replace each letter with the letter in the same row at the other rectangle corner.
  6. The complete output package contains no literal spaces. The formatting metadata is encrypted with AES-GCM, and an HMAC verifies the package before decryption.
Security flaws and improvements
  1. Digraph frequency analysis: Playfair substitutes pairs of letters, but language patterns can still be detected, especially in long messages.
    Mitigation: a fresh random salt derives a different grid for each message, reducing direct comparisons across messages. This does not remove frequency analysis within one message or prove the cipher secure.
  2. Known-plaintext attack: if an attacker knows some plaintext and its ciphertext, the correspondence can help recover or constrain the message's Playfair grid.
    Mitigation: the per-message salt reduces grid reuse across messages. A known-plaintext attack against a sufficiently long individual message may still be possible; this limitation cannot be eliminated while keeping classical Playfair rules.
  3. Key-search / dictionary attack: common passphrases are easier to guess than random, high-entropy ones.
    Mitigation: use a long, unique passphrase. PBKDF2-HMAC-SHA-256 with 600,000 iterations increases the cost of each password guess, but cannot make a weak passphrase strong.
  4. Ambiguous padding letter: filler letters such as X can be confused with letters that were in the original text, for example in a word with repeated letters.
    Mitigation: this implementation records the exact filler positions in encrypted metadata and removes only those positions after decryption. Original X letters are preserved.
  5. Undetected ciphertext modification: classical Playfair has no built-in integrity check, so a changed ciphertext may decrypt to altered text without warning.
    Mitigation: a separate HMAC-SHA-256 authenticates the version, salt, IV, Playfair ciphertext, and encrypted metadata. Decryption is rejected if verification fails.
  6. Spaces, case, punctuation and J/I: classical Playfair normally removes spaces and punctuation, converts to uppercase, and merges I/J.
    Mitigation: this page preserves those details in encrypted metadata and restores them after decryption. They do not appear as literal spaces in the transmitted package.

Important limitation: the classical same-row, same-column and rectangle rules remain unchanged. These additions improve key derivation, formatting recovery and tamper detection, but do not eliminate the inherent cryptanalysis weaknesses of Playfair. The package length still reveals an approximate message size. This is an educational construction, not an independently audited secure cipher.
