Caesar Cipher

Classical encryption and decryption (A–Z and a–z), brute-force demonstration, history, and security weaknesses.

1. Encryption / Decryption

The classical Caesar rule is unchanged: each A–Z letter is shifted by the numeric key. The transmitted package has no literal spaces. Original spaces, letter case, digits, and punctuation are recorded in Base64URL-encoded formatting metadata and restored during decryption. Important: Base64URL is encoding, not encryption, so this hides spaces from the displayed package but does not keep the metadata secret. The Caesar key must be an integer from 1 to 25; 0, 26, 27, and other out-of-range values are rejected.

2. Attaquant (force brute)

L'attaquant peut coller le paquet complet : l'outil extrait sa partie de lettres et essaie tous les décalages utiles, de 1 à 25. Les clés 0, 26 et toutes les valeurs hors de 1 à 25 sont refusées : décaler de 26 ramène exactement au même texte (ABC → ABC), donc il n'apprend rien. De plus, un décalage à gauche de k est identique à un décalage à droite de 26 − k : tester 25 décalages dans un seul sens couvre donc toutes les clés possibles. 4. Caesar Cipher Weaknesses and What This Version Improves

The classical Caesar shifting rule is deliberately unchanged. Some usability problems can be improved around it, but the core cryptographic weaknesses cannot be removed without replacing or changing Caesar itself.

Main weaknesses

  • Tiny key space — not fixed: there are only 25 useful shifts. The brute-force panel tests them all, so a determined attacker can recover the message quickly.
  • Frequency analysis and index of coincidence — not fixed: every letter is always replaced by the same shifted letter. Letter frequencies and the language's statistical structure remain, making the shift easy to identify.
  • Known-plaintext and chosen-plaintext attacks — not fixed: a known plaintext/ciphertext letter pair can reveal the shift. If an attacker can request encryption of selected text, the shift is also easy to recover.
  • Dictionary words and probable-word attacks — not fixed: common words can reveal the shift. ROT13 is especially weak; applying ROT13 twice restores the original text.
  • Deterministic encryption and key reuse — not fixed: with the same shift, the same letter always becomes the same letter, and reusing the shift gives an attacker more samples to analyze.
  • Message structure and spaces — only hidden visually: the transmitted package has no literal spaces, but the layout metadata is Base64URL-encoded, not encrypted. Anyone can decode it and inspect the original spaces, punctuation, and other non-letter characters.
  • Uppercase/lowercase, digits, and punctuation — handled for restoration: this page records the original formatting and restores it after decryption. This is a usability improvement, not extra confidentiality, because the metadata is not secret.
  • No integrity or authentication — not fixed: classical Caesar has no way to reliably detect ciphertext changes or prove who sent a message. This version does not add a second secret or an authentication mechanism, so tampering may go undetected or produce a decoding error.
  • Zero or equivalent shifts — blocked by validation: key 0, 26, 27, negative numbers, and non-integers are rejected. This prevents accidental no-op keys, but does not make the remaining shifts harder to guess.
  • Message length remains visible — not fixed: removing literal spaces does not hide the overall package length, so an observer can still estimate the message size.
  • Kerckhoffs' principle — not fixed: the algorithm is assumed to be public, so all security depends on the key; 25 possibilities are far too few for meaningful secrecy.

What this implementation improves

  • One key only: the numeric Caesar shift is the only cipher key. There is no additional passphrase.
  • No literal spaces in the transmitted package: the shifted letters are joined together, and formatting information is placed in a continuous encoded field. This removes visible word boundaries from the displayed package, but it does not encrypt that formatting field.
  • Exact formatting restoration: the original spaces, capitalization, punctuation, digits, and other non-A–Z characters are restored after decryption.
  • Strict key validation: only integer shifts from 1 to 25 are accepted. This stops accidental use of shifts equivalent to zero.
  • Educational brute-force demonstration: the attack tool can extract the letter ciphertext from a package and test all 25 shifts, illustrating why Caesar is weak.

What is not fixed: frequency analysis, brute force, known-plaintext attacks, the tiny key space, and the lack of integrity/authentication remain. The space-free package is a formatting/transport convenience, not a secure replacement for encryption of the metadata. This project is suitable for learning; do not use Caesar to protect real confidential information. For real security, use a standard authenticated-encryption scheme such as AES-GCM.
