Password System

Three password types, the attacks against them (dictionary and brute force) with measured times, and the solutions to protect them.

1. Password generator

Passwords are generated with the browser's secure random generator. You can also type your own password to check it against the rule.

Type 1 — 3 characters, each 0 or 1

2³ = 8 possible combinations. Example: 101

Type 2 — 4 characters, each 1, 2, 3 or 4

4⁴ = 256 possible combinations. Example: 2413

Type 3 — characters a-z, A-Z, 0-9, + and *

2. Attacks and execution time

Dictionary attack: the attacker tries a short list of very common passwords (123456, password, 1234 ...). It is fast, but it only works if the password is on the list.

Brute force: the attacker tries every combination until he finds the right one. It always works, but the time grows with the number of combinations.

Minimum time: the attacks above are optimised: the dictionary is tried first (a few tries), and brute force only enumerates the known length for Types 1 and 2 (8 or 256 candidates), or the lengths 1, 2, 3 … in order for Type 3.

Example, Type 1, password 101:
Dictionary: 000, 111, 101 → found in 3 tries.
Brute force: 000, 001, 010, 011, 100, 101 → found in 6 tries.

The test uses the passwords of section 1 (a random one is generated if a field is empty or invalid).

3. Password protection

AttackSolutionSimple explanation and example
Dictionary attack Refuse common passwords (blacklist). Mix letters, digits and symbols. The attacker only tries well-known passwords, so a password that is not on his list resists.
Example: "password" → refused. "Kt7+m2*Q" → accepted. The generator above already warns about common passwords.
Brute force (tiny space: Types 1 and 2) Use a longer password and a bigger alphabet (Type 3, 12 characters or more). Each extra character multiplies the number of tries by 64.
Example: 8 characters → 2.8×10¹⁴ combinations; 12 characters → 4.7×10²¹.
Types 1 and 2 (8 and 256 combinations) can never be made safe by length alone.
Online brute force (guessing on the login page) Progressive lockout: limit the number of attempts and make the attacker wait. After 3 failures the account waits 30 s, then the wait doubles at every failure (max 24 h).
Try the simulation below: Type 2 goes from "instant" to months.
Stolen password database (offline attack) Never store passwords in clear text: store a hash with a random salt (bcrypt / argon2 in real systems). A hash is a one-way fingerprint. The salt is a random text added before hashing, so two users with the same password get different fingerprints.
Try the demo below.
Password guessed or stolen anyway Two-factor authentication (2FA). Even with the right password, the attacker also needs a second proof (a code sent to the phone).
