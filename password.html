Password System

Creation and validation of the three password types, number of possible combinations, and tests with measured execution time of the attacks.

Password generator and validation

Passwords are generated with the browser's secure random generator. You can also type your own password, then click Check: the page tells you if it respects the rule of the type, and what to change if it does not.

Type 1 — 3 characters, each 0 or 1

2³ = 8 possible combinations. Example: 101

Type 2 — 4 characters, each 1, 2, 3 or 4

4⁴ = 256 possible combinations. Example: 2413

Type 3 — characters a-z, A-Z, 0-9, + and *

Attack tests and execution time

Both attacks (dictionary, then brute force) are run on the 3 passwords above (a random one is generated if a field is empty or invalid). The times are measured in your browser.

Dictionary attack

A dictionary attack tries likely passwords from a word list, starting with the most common ones. Add your own words to see how a larger, more realistic list changes the attack.

Protection against dictionary attacks

Protect the current target password to see the salted hash that a real database should store instead of the plain password.

Even if the attacker's dictionary contains this exact password, they only gain something if they can compute the hash with the matching salt — this defeats pre-computed dictionaries (rainbow tables), and each individual guess still has to go through this extra hashing step.

Creation-time protection: checkPwd() already warns when a password is in the common-password dictionary, helping users reject known-weak passwords before they are used.
