Password System

Creation and validation of the three password types, number of possible combinations, and tests with measured execution time of the attacks.

Password generator and validation

Passwords are generated with the browser's secure random generator. You can also type your own password, then click Check: the page tells you if it respects the rule of the type, and what to change if it does not.

Type 1 — 3 characters, each 0 or 1

2³ = 8 possible combinations. Example: 101

Type 2 — 4 characters, each 1, 2, 3 or 4

4⁴ = 256 possible combinations. Example: 2413

Type 3 — characters a-z, A-Z, 0-9, + and *

Attack tests and execution time

Both attacks (dictionary, then brute force) are run on the 3 passwords above (a random one is generated if a field is empty or invalid). The times are measured in your browser.

Dictionary attack

A dictionary attack tries likely passwords from a word list, starting with the most common ones. Add your own words to see how a larger, more realistic list changes the attack.

Dictionary Protection

1. Block common passwords

When a user creates a password, check it against a demonstration list of common or compromised passwords. Click Check above: if the password matches, it is vulnerable to dictionary attacks and the user should choose a stronger password. For example, common passwords include 123456 and password123.

A password not found in our list is not guaranteed to be secure; the list is only a small demonstration.

This checks the combined password-type dictionaries on this page. A password not found in these demonstration lists is not guaranteed to be secure.

2. Limit login attempts

Repeated failed attempts trigger a temporary delay, helping to defend against dictionary attacks against a login page. This browser-only simulation can be bypassed; a real application must enforce rate limits on its server.

Brute Force Attack

Brute Force Protection

Simulate a login with a limited number of attempts. After three failed tries, this demonstration temporarily blocks login for 10 seconds. This browser-only example can be bypassed; real applications must enforce protections on the server.
