Integrity

Side A encrypts the message with Caesar, Hill, or Playfair, then calculates a 16-bit checksum from the encrypted payload. Side B checks the checksum before decrypting; length and padding data preserve the original message.

1. Encryption (Sender)

Allowed characters: a–z, A–Z, 0–9, *, + and spaces. Other characters are removed.

Attacker — Intercept and modify the message

The attacker sits on the channel between Side A and Side B. They intercept the encrypted packet (ciphertext|checksum|length|padding data) and randomly alter some characters of the ciphertext. The original checksum is left untouched, so Side B should detect the change.

Side B — Decrypt and verify integrity

Recalculate the checksum from the received encrypted payload and compare it with the attached value before decrypting. Length and padding data help restore the original message accurately. Use the attacker simulation above to test tamper detection. This simple checksum is not cryptographic authentication and can be altered or recomputed.

Only the encrypted message before the first "|" can be changed. Spaces are not allowed.
